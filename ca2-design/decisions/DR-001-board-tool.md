## Context

As a team we have to decide on a board management tool to manage backlog items and keep in sync over the duration of this project. We have to go through different board tool provders like Azure Devops, Microsoft Planner, Jira etc. and find the best fit for our needs. 

## Decision

As a group, we decided to use github issues/projects to manage our backlog items. We chose this as it keeps everything in one place (github repository) so it is going to be easier to navigate between backlog items and project on a singular platform. 

## Rationale

We chose github projects/issues because it is intergrated within github where the existing project repository is held. This makes the workflow of going between board items and the project repository much more natural rather than going between individual services. 

We were mainly focused on a smooth workflow between the board and the repository so github project/issues was the most natural decision. 

## Alternatives considered

| Option | Reason not picked |
|--------|-------------------|
| Micorsoft Azure DevOps | We decided not to use Azure DevOps as our board tool because the project repository already sits on github |
| Microsoft Planner | Same reason as Azure. It is easier to manage the board tool in the same place as the repository |
| Jira | Although Jira has much more features for board planning, it is still isolated as a seperate service to our repository |
