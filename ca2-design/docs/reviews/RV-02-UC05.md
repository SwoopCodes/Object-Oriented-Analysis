## What was checked

I went through the UC05 files and compared them against each other.

1. I checked the SSD, the contract and the first message in the sequence diagram use the same name and parameters. They all use checkInMember(memberNumber).
2. I went through each postcondition in the contract and looked for the message in seq-checkInMember that makes it happen. All five are there.
3. I checked every failure in the use case and contract has an alt branch and a Gherkin scenario. Some are missing (rows 1, 2, 3 and 5).
4. I checked every message in the sequence diagram and every operation in crc-UC05 is in the class diagram. They all are, apart from create() messages, which are constructors.
